    15→## 1. App Identity
    16→- **Name**: TeliPally
    17→- **One-line idea**: A free live TV streaming app that lets users browse thousands of global TV channels by country or category and stream live news.
    18→- **Elevator pitch**: TeliPally provides free access to thousands of live TV channels from around the world, organized by country and category. Users can easily discover and stream their favorite news programs and shows without subscription fees. The app leverages the open-source iptv-org directory to offer a comprehensive, constantly updated channel lineup.
    19→- **Platforms**: Web + Progressive Web App (PWA)

    22→
    23→| Decision | Alternatives Rejected | Rationale | What Breaks If Wrong | Revisit Trigger |

    25→| Platform: Web + PWA | Native mobile apps only, Web only | Wider accessibility, easier development, cross-platform support, no app store approval needed | Limited user reach, higher development cost, platform lock-in | User adoption metrics below 15% in target regions |

    32→## 3. Problem
    33→Current live TV solutions require expensive cable/satellite subscriptions or involve complex, illegal streaming setups with malware risks. Legal streaming services often have regional restrictions and require multiple subscriptions. The iptv-org directory exists but lacks a user-friendly interface for browsing and streaming. Users need a simple, legal, free way to access global live TV content without technical expertise or financial commitment.

   206→## 6. Authentication Method
   207→
   208→**Mechanism**: NextAuth.js with database sessions
   209→**Session Strategy**: Database sessions stored in PostgreSQL, with secure httpOnly cookies
   210→**Password Rules**: Minimum 8 characters, must include uppercase, lowercase, and number
   211→**Email Verification**: Required for registered users, verification link sent on signup
   212→**Reset Flow**: Password reset email with secure, time-limited token
   213→**Protected Routes**: Any API endpoint starting with `/api/user/` requires authentication
   214→**Revocation Story**: Sessions are stored in the database with a `expires` field. When a user logs out, their session is immediately deleted from the database. If a user changes their password, all existing sessions are invalidated.

   394→## 4. Interval & Time Convention
   395→
   396→Intervals are interpreted as [start, end) - inclusive of start time, exclusive of end time. All timestamps are stored in UTC timezone and converted to user's local timezone only for display purposes. This follows the TRD decision to use date-fns for date/time handling.

   598→## 6. Non-happy-path Behaviour
   599→
   600→**Offline**: When the app detects no internet connection, it shows an offline banner and stores user actions locally. Upon reconnection, it syncs the actions with the server. For streaming, it shows a cached channel logo with a "no connection" message.
   601→
   602→**Permission Denied**: When a registered user tries to access protected features without authentication, they're redirected to the login screen with a message explaining the action requires login.
   603→
   604→**Stale/Conflicting Write**: When a user updates their watchlist from multiple devices, the app uses an optimistic UI approach. If a conflict is detected (e.g., channel removed from another device), it shows a notification and refreshes the data.
   605→
   606→## 7. Auth Flow
   607→
   608→**Signup**: User enters email/password, submits form. System validates input, creates user account, sends verification email. User is logged in immediately but can't access features until verified.
   609→
   610→**Login**: User enters credentials, submits form. System validates credentials, creates session, redirects to home. "Remember me" option persists session for 30 days.
   611→
   612→**Logout**: User clicks logout button, session is terminated on server and client, redirected to home page.
   613→
   614→**Password Reset**: User enters email, submits form. System sends time-limited reset link. User follows link, enters new password, account is updated.
   615→
   616→**Email Verification**: User clicks verification link from email. System marks email as verified, user gains full access to features. Resend option available if verification email not received.
   617→

   619→
   620→Payment and upgrade flows are out of scope for version 1. TeliPally will remain free and ad-supported without premium features.
